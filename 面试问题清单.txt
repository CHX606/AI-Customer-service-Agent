AI Customer Service Agent 面试问题清单
========================================

| 类别         | 面试官可能提出的问题                                             | 主要考察点                 | 可以回答的解决方向                                      |
|--------------|----------------------------------------------------------------------|----------------------------|---------------------------------------------------------|
| 检索召回     | 用户换一种说法，知识库检索不到怎么办？                             | 语义召回、口语表达、同义词 | 查询改写、混合检索、补充同义问法、优化 Embedding       |
| 检索准确性   | 检索结果看起来相关，但实际上不能回答问题怎么办？                   | 误召回、结果排序           | Reranker 重排、相关性判断、只保留高质量资料             |
| 无答案处理   | 知识库没有答案时，怎么防止模型胡编？                               | 幻觉、可靠拒答             | 判断资料充分性、低置信度拒答、转人工客服                |
| 效果评测     | 你怎么证明检索效果真的好？                                         | 数据驱动、评测意识         | 构建标注测试集，计算 Recall@K、命中率、拒答准确率       |
| 回答评测     | 检索正确就一定能生成正确答案吗？                                   | 生成质量、忠实度           | 评估答案正确性、完整性、引用正确性和事实一致性          |
| 多轮对话     | 用户说“那什么时候恢复”，系统怎么理解他在问什么？                   | 上下文理解、指代消解       | 将历史上下文和当前问题改写成完整检索问题                |
| 历史管理     | 对话越来越长，成本和延迟越来越高怎么办？                           | 上下文管理、Token 成本     | 历史截断、对话摘要、只保留相关上下文                    |
| 精确查询     | 套餐名、错误码、订单号等精确内容，向量检索效果不好怎么办？         | 向量检索局限               | BM25 关键词检索与向量检索融合                           |
| 文档结构     | 操作步骤或表格被切散后，检索结果不完整怎么办？                     | 文档解析、切块策略         | 按标题和段落切块、父子块检索、保留表格结构              |
| 来源引用     | 用户怎么知道回答依据来自哪份资料？                                 | 可解释性、可信度           | 保存标题、章节、版本等 metadata，并在回答中展示引用     |
| 内容冲突     | 新旧知识文档内容冲突时，系统应该相信哪一个？                       | 数据治理、内容优先级       | 文档版本、生效时间、来源权重、失效标记                  |
| 知识更新     | 客服规则更新后，怎么同步到知识库？                                 | 数据更新能力               | 增量更新、文档哈希、删除失效内容、索引版本管理          |
| Agent 选型   | 为什么使用 Agent，而不是普通的 RAG 流程？                          | 架构取舍                   | 单工具可用确定性 RAG；多业务工具场景体现 Agent 价值     |
| 工具调用     | Agent 选错工具或者传错参数怎么办？                                 | Agent 可靠性               | 参数校验、工具权限、调用前检查、失败兜底                |
| 高风险操作   | 如果未来 Agent 可以退款或取消订单，怎么避免误操作？                | 业务安全                   | 查询和写操作分级，高风险操作二次确认或人工审核          |
| 响应速度     | 一次问答需要多次模型和检索调用，响应太慢怎么办？                   | 性能优化                   | 模型复用、缓存、并行调用、减少不必要的 Agent 判断       |
| 调用成本     | 用户量增加后，模型调用成本过高怎么办？                             | 成本控制                   | 小模型路由、答案缓存、限制上下文、按难度选择模型        |
| 高并发       | 同时有大量用户访问，系统能否承受？                                 | 并发、扩展能力             | 异步处理、连接复用、队列、限流、服务横向扩展            |
| 会话隔离     | 不同用户使用相同或伪造的 session_id 怎么办？                       | 身份认证、数据隔离         | 登录鉴权、服务端生成会话、校验会话所有者                |
| 会话存储     | 服务重启后会话消失，多实例之间也无法共享怎么办？                   | 状态持久化                 | 使用 Redis 或数据库保存会话，并设置过期时间             |
| 模型故障     | 大模型接口超时、限流或者不可用怎么办？                             | 容错、服务降级             | 超时、有限重试、备用模型、降级回答、转人工              |
| 重复执行     | 工具调用失败后重试，会不会重复创建工单或重复退款？                 | 幂等性                     | 幂等键、操作状态检查、唯一请求编号                      |
| 提示注入     | 用户要求忽略规则并输出内部文档怎么办？                             | Prompt Injection、安全边界 | 权限控制、资料分级、敏感信息过滤、输出审查              |
| 隐私保护     | 用户在聊天中输入手机号、订单号等隐私数据怎么办？                   | 数据安全、合规             | 数据脱敏、最小化存储、访问审计、设置数据保留期限        |
| 系统监控     | 系统上线后，怎么发现回答质量下降？                                 | 可观测性                   | 监控无结果率、转人工率、重复提问率、响应时间和错误率    |
| 用户反馈     | 用户反馈“答案没用”后，如何让系统持续改进？                         | 反馈闭环                   | 收集差评原因、补充评测集、优化知识库并进行版本对比      |
| 人工转接     | 什么情况下应该转人工客服？                                         | 业务边界                   | 无答案、低置信度、高风险业务、用户明确要求时转人工      |
| 项目价值     | 和普通聊天机器人相比，你的系统有什么价值？                         | 项目定位                   | 基于企业知识回答、可更新、可追溯，并能扩展业务工具      |
| 生产差距     | 当前 Demo 距离真正上线还缺少什么？                                 | 系统性认知                 | 评测、权限、监控、持久化、容错、安全、更新和人工兜底    |
